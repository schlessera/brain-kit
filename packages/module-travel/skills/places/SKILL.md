# Places

Keeps the visited-places record: one `places/` file per country, city, town or
notable spot. A place does not store its own visits. A visit is recorded once,
on the journey or trip that made it, and the place is linked to it. Counts,
first/last dates, countries visited and the per-year lists in
`places/_index.md` are generated by `brain travel sync`.

## Prompts

1. **Which place**: its name and kind (`country`, `city`, `town` or `spot`)
2. **Within**: the country, or city/town, it belongs to — check `places/`
   for an existing record first
3. **Coordinates**: only if the user gives them, or confirms the `location`
   that `brain travel photo` reported for a photo taken there. Otherwise
   leave them unknown
4. **Which visits**: the journey or trip, and which of its visits, reached it

## Actions

### Record a place

1. Search `places/` and `brain search` for the place, including other
   spellings. Never create a second record for the same place.
2. Create it under its parent's folder (`places/ithaca.md`,
   `places/ithaca/headland.md`) with core frontmatter plus `type: place`,
   `place_kind`, `parent_place` (the parent's complete path, such as
   `places/ithaca.md`) and `coordinates` (`{lat, lon}` or `null`). Create a
   missing parent country first. A hierarchy runs country → city/town → spot.
3. Link the visits. Prefer adding the place's path to the owning document:
   `places:` on a journey or trip applies to every visit, `places:` on one
   visit applies to that visit. To link a visit from the place side instead,
   add `{document: <journey or trip path>, visit: <visit id>}` to the place's
   `visits:`. Either way the visit counts once.
4. Do not write `visit_count`, `first_visit` or `last_visit`; sync derives
   them and ignores stored values.

### Answer "where have we been?"

Run `brain travel sync`, then read `places/_index.md`: "Countries visited"
counts a country's own visits and those of every place within it, "By year"
lists the places reached each year. An `unknown` date or coordinate means
the record does not have it; say so rather than estimating.

### Always finish with

`brain travel validate`, then `brain travel sync`. Validation names an
unknown place path, a broken hierarchy or a visit reference that does not
exist; fix the record.

## References

### Files to Read
- `places/_index.md` and the existing `places/` records
- The journey (`travel/`) or trip (`trips/`) whose visit reached the place

### Files to Write/Modify
- Create/modify: `places/**/*.md`
- Modify: `places:` on the journey or trip that made the visit

### Workflow Position
- **Before**: `/trip-log` or `/plan-travel` recorded a visit
- **After**: nothing; the registry is regenerated by sync
