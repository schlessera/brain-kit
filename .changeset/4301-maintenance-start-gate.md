The asynchronous direct-spawn maintenance and transport launches (`launchMaintenanceWorker`, `runMaintenanceWorker`) now wait at a fail-closed start gate before their payload starts (#4301): a server that dies before release never starts the payload. Stdin, output caps, exit codes and cleanup are unchanged. The gate shell starts from an empty environment; after release the payload gets exactly the variables, in the order and bytes, an ungated launch gives it, so nothing the caller's environment selects runs before release. The payload keeps its rlimits and prlimit's own diagnostic; with no rlimit prefix, a missing executable still exits 1 with bubblewrap's `execvp` message (any other exec failure of that first program reports `env`'s message and 126 or 127). Two more residual differences: a variable whose name is empty or contains `=` is refused before spawn with `WorkerHostError` (main's bubblewrap refused it with `setenv failed`), and so is a command whose first word contains `=`, which main ran but `env` would read as an assignment. A caller's timeout counts from the spawn on a monotonic clock, normalized as Bun's timers normalize it (zero disables it), and a deadline that passes before release stops the launch with SIGKILL, as the caller's own timer would. An abort before release rejects with its own reason. A stopped launch is frozen and its children are stopped before its supervisor is killed, and its status and gate descriptors close once it exits. A bubblewrap that fails its own setup still reports its own exit code and stderr. One intended difference: a gate step that fails while bubblewrap is still alive stops it and throws `WorkerHostError`. The synchronous form (`runMaintenanceWorkerSync`) is unchanged.
