The host's Google credential (#4206): four new environment variables and the availability check the Google tools will use. `BRAIN_UI_GOOGLE_HOME` names the gog home (configuration and encrypted file keyring), `BRAIN_UI_GOOGLE_KEYRING_PASSWORD` its keyring password, `BRAIN_UI_GOG_PATH` the pinned gog release binary and `BRAIN_GOOGLE_LEDGER` the shared Google ledger (default beside the UI database). They are read once at boot, the password into a closure, and none of them, nor any `GOG_*` name, reaches a worker, a host-boundary child or a cron job.

The home is checked at first use and on every later use, never at boot. It must be absolute, a directory with mode 0700 owned by the server's user, and neither inside nor holding the brain, the database directory, a host path workers see (the server's HOME, the Bun runtime, the server's own installation and the packages it loads, the system directories and `/etc` files workers bind, `/proc`, `/dev`) or a temp area (`/tmp`, `/var/tmp`, `/dev/shm`, `TMPDIR`), with symbolic links resolved first. A home that fails a check makes Google answer `unavailable` with the reason and a server log line, and the server boots and serves chats as before; a repaired mode or owner is used on the next call. Every worker view covers the home as it resolved at boot, a cron job's included (the cron runner reads `BRAIN_UI_GOOGLE_HOME` from the emitted environment for that alone), but only where a mask is safe for every launcher to lay: an existing directory that is neither inside nor holding the brain, holds none of the other areas, lies inside no host path workers see except the server's HOME, and lies below none of `/tmp`, `/proc` and `/dev`, so a misplaced setting never stops a worker from starting. A home strictly inside the server's HOME, the database directory or another temp area is still covered while its check refuses it. With a separate worker identity (`BRAIN_UI_WORKER_IDENTITY_HELPER`), a home behind a directory that identity cannot search gets no mask, because no worker can reach it and the launcher would otherwise widen the mask over the brain and refuse every launch; a check refuses it once that directory opens. The server holds the home open from boot, so a directory deleted and made again in its place is told from it whatever the filesystem records, while a chmod or chown is not. The home must therefore exist before the server starts; one created, replaced or moved after boot is refused until the server restarts. The default homes under the server's HOME are covered too, where they exist at boot, by the same rules: gog's own (`~/.config/gogcli`, `~/.local/share/gogcli`, `~/.local/state/gogcli`, `~/.cache/gogcli`) and the standalone `brain google` home (`~/.local/share/brain/google`), each as the directory it resolves to, so one linked outside HOME is covered at its target. A connected check that an unavailable answer overtakes neither answers available nor stands as the cached success. There is no Google tool yet: the check combines the home, the gog pin and whether the policy's account alias is connected (one read-only label listing, cached for five minutes) into a status the tools and status surfaces will read, and it never rejects: an unexpected failure answers `probe_failed`.
