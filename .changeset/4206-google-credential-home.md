The host's Google credential (#4206): four new environment variables and the availability check the Google tools will use. `BRAIN_UI_GOOGLE_HOME` names the gog home (configuration and encrypted file keyring), `BRAIN_UI_GOOGLE_KEYRING_PASSWORD` its keyring password, `BRAIN_UI_GOG_PATH` the pinned gog release binary and `BRAIN_GOOGLE_LEDGER` the shared Google ledger (default beside the UI database). They are read once at boot, the password into a closure, and none of them, nor any `GOG_*` name, reaches a worker, a host-boundary child or a cron job.

The home is checked at first use and on every later use, never at boot. It must be absolute, a directory with mode 0700 owned by the server's user, and neither inside nor holding the brain, the database directory, a host path workers see (the server's HOME, the Bun runtime, the system directories and `/etc` files workers bind, `/proc`, `/dev`) or a temp area (`/tmp`, `/var/tmp`, `/dev/shm`, `TMPDIR`), with symbolic links resolved first. A home that fails a check makes Google answer `unavailable` with the reason and a server log line, and the server boots and serves chats as before; a repaired mode or owner is used on the next call. Every worker view covers the home as it resolved at boot, a cron job's included (the cron runner reads `BRAIN_UI_GOOGLE_HOME` from the emitted environment for that alone), but only where a mask is safe to lay: an existing directory that is neither inside nor holding the brain and holds none of the other areas, so a misplaced setting never stops a worker from starting. A home strictly inside one of them, such as the server's HOME, is still covered while its check refuses it. The home must therefore exist before the server starts; one created, replaced or moved after boot is refused until the server restarts. gog's own default directories under the server's HOME (`~/.config/gogcli`, `~/.local/share/gogcli`, `~/.local/state/gogcli`, `~/.cache/gogcli`) are covered too, where they exist at boot. There is no Google tool yet: the check combines the home, the gog pin and whether the policy's account alias is connected (one read-only label listing, cached for five minutes) into a status the tools and status surfaces will read, and it never rejects: an unexpected failure answers `probe_failed`.
