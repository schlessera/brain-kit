Changed (breaking supported input, #2876): the host writers a turn drives outside its worker now refuse the turn's protected paths. An autonomous turn's exactly approved application uses the protection of the governance policy it was admitted under, as a hosted turn's application already did, so an approved autonomous write to a protected path (the built-in tiers or anything in the policy's `protect` list) no longer applies and returns `policy_denied`. A hosted conversation's `inbox_add` refuses the same way when its staging directory `.brain-ui/inbox`, an ancestor, or the arrival it would stage, publish or compensate is protected; nothing is staged and no inbox item is created. Every host writer, the application route and image masks included, now compares a target both as named and where its links lead: a link into a protected path, a protected path that is itself a link to the target, and a link into a `.env*` name all refuse. To let an autonomous turn or `inbox_add` write there again, remove the path from the policy's `protect` list, or for a built-in tier B path add it to `release`.
