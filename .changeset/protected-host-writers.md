Changed (breaking supported input, #2876): the host writers a turn drives outside its worker now refuse the turn's protected paths. An autonomous turn's exactly approved application uses the protection of the governance policy it was admitted under, as a hosted turn's application already did, so an approved autonomous write to a protected path (the built-in tiers or anything in the policy's `protect` list) no longer applies and returns `policy_denied`. A hosted conversation's `inbox_add` refuses the same way when its staging directory `.brain-ui/inbox`, an ancestor, or the arrival it would stage, publish or compensate is protected; nothing is staged and no inbox item is created. A protected path that is itself a link, or a `.env*` name that is one, now also protects where it leads, for every host writer including the hosted application route and image masks (`policy_denied`), and an image mask's scratch prune keeps those files. A target reached through a link keeps the application route's `alias_denied` refusal; inbox staging, which follows links, refuses a link into a protected path or a `.env*` name as protected. To let an autonomous turn or `inbox_add` write there again, remove the path from the policy's `protect` list, or for a built-in tier B path add it to `release`.
