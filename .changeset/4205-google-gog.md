Adds the internal, Bun-only entry point `@schlessera/brain-common/internal/google-gog` (#4205): the gog transport the Google host tools and the standalone CLI will run every operation through. `createGogTransport({ binary, account, environment })` answers `execute(operation, input)` with a validated record or a coded error, and nothing above it sees argv or gog's JSON. It accepts only gog 0.48.1's release binaries, pinned by sha256 per platform, and before first use checks the binary's and its directory's owner and mode, the hash, `gog version` and every command, flag and positional the catalog uses in `gog schema --json`; it re-checks the identity of the file the path resolves to and of its directory before every call (ctime, mode and owner included, so a rewrite that restores the mtime is seen, and a symlink pointed at another file is a change), verifies again whenever it changed, and tries a probe that timed out, or a check that failed unexpectedly (a read of the binary that failed, say), again after a 30-second backoff, without a restart. Argv is built only from validated input, with one `--enable-commands-exact` per call, `--readonly` on every read and `--gmail-no-send` everywhere but the host send path; the environment is an allow-list built from the host's values; bodies go through stdin; stdout is capped at 8 MiB, stderr never surfaces, timeouts kill the process group, a read retries once on gog's retryable exit and a write never retries. Strict codecs decode search, thread, message, raw draft and label reads; a search reads each hit's thread, because gog's search output carries only the first message's labels, and refuses a page with more hits than it asked for before reading any. Write codecs are not part of this release.
