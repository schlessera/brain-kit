Hosted chat turns can search and read the owner's Gmail through six new host tools (#4207): `brain_google_gmail_search` and `brain_google_gmail_read`, and the write tools `brain_google_gmail_modify`, `brain_google_gmail_trash`, `brain_google_gmail_draft` and `brain_google_gmail_send`, which answer `unavailable` until the write engine lands. All six are in every interactive session's fixed roster on Claude (`mcp__brain-ui__*`, always loaded) and pi, whether or not the brain's policy enables Google, and in no autonomous roster. The host decides each read under the turn's frozen governance policy's `google` block: the brain's owner account only (an owner login, or the ambient principal where the auth mode makes it the owner; never a proxy's other upstream users), Google enabled with an account alias and `gmail` listed, and data routing as the provider-policy recipient `google`; a call those checks refuse sends Google nothing. Reads come in two views. `structured` returns only host-validated ids, label ids and names, timestamps, counts, size buckets and flags and leaves the session untainted; `content` adds senders, recipients, subjects, snippets and text bodies (32,768 characters per message, 131,072 per thread), marked untrusted, and taints the session with the new governance source `google_result`, shown as "Gmail content", before it returns, withholding the result when that record fails. Every call the host decides records the new governance event `google_call` (tool, operation, view, outcome, refusal code and reason), which is never safety evidence. `google.gmail.hidden_labels` keeps a thread out of every search and makes every read of it answer `not_found`, as a missing one does. Search pages carry a host-minted cursor bound to the conversation and query; Google's page token never reaches the model. Both backends' fixed system brief gains one line naming the tools and telling the model that `gog`, `curl` and WebFetch cannot act as the user on Google, that the structured view keeps a session untainted, and to report `unavailable` or `policy_denied` and stop; a session retained earlier keeps its brief. A new internal route, `GET /api/sessions/:id/google/gmail/messages/:message/body`, serves the chat's owner the full body of a message a read in that session returned, for display only. The SDK adds the contracts, payload and result schemas, `handleGoogleTool`, `BackendBridge.google` and the `googleTools` brief option.
