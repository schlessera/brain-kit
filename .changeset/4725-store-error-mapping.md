The file and graph stores, the What's up briefing and the three `/api/vpn-check` readers now share the API client's one failure mapping (#4725): a failed request is an `ApiRequestError` with its HTTP status and parsed body, and its message is the host's `error`, then `reason`, then `code`, then `HTTP <status>`. Three visible texts change: a file or graph failure whose body has `reason` or `code` and no `error` reads as that text instead of `HTTP <status>`; a graph failure whose body is not JSON reads as the status text; and the What's up modal now uses the same mapping: its failure message is the body's `error`, then `reason`, then `code`; for a body that is not JSON, such as a proxy's HTML 502, the status text alone (`Bad Gateway`); and `HTTP <status>` only for a JSON body with none of the three fields or an empty status text. It never reads `HTTP <status>: <status text>` any more. Routes, request headers and the public `BrainApi` type are unchanged.
