`trackCoverage` (and `brain geo track --compare`) now answers ordinary recorded tracks instead of returning `unknown: ["analysis_limit_exceeded"]` (#4814). It used to compare every sample of A with every edge of B and refused up front when samples × edges of B exceeded 5,000,000, which a 20 km track with 2,000 points already did. Coverage now finds each sample's candidate edges through a latitude/longitude grid over B and tests only the edges that can lie within the tolerance plus half a sample step, which cannot change any result: wherever coverage answered before, the ratio, covered length, bounds, status, reasons and method are exactly the same. Inputs near a pole or across the date line test every edge, as before. The 5,000,000-comparison bound now counts the comparisons performed and refuses only when that count is reached; the 100,000-sample bound still refuses before any comparison, both limit values and every output field and reason are unchanged. The test that pinned a refusal for 1,000 identical short sections in B now uses sections that run the whole length of A, since the short ones are now answered. Point-of-interest replies along a track build the track's edge list once per reply instead of once per returned element.
