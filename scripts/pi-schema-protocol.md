# Pi schema provider acceptance

This private #563 instrument holds the production `show_block` description and
accepted inputs fixed. It runs one fresh `openai-codex` / `gpt-6.1-sol` turn for
each of `flat`, `shared`, and `shared-trimmed`, sequentially. These three turns
test provider request acceptance and a parsed handler call. They cannot estimate
call rate, behavioral equivalence, cache savings or a cost reduction. #336's
separate 81 fresh Sonnet 5.5 cells supply the Claude behavior evidence.

The prompt is byte-identical to the approved #550 `note-approaches` prompt. All
31 original fictional corpus bytes must match its published manifest and the
shared #336 complementary corpus review. Forms/options and actual draft-2020-12
parameters match the #336 schema source, including three `$defs` in each shared
form. Production keeps its shipped default during measurement. Any changed
prompt, form, source, runtime, corpus, guard or controller fails frozen admission.
The manifest binds all tracked source, owned instrumentation, independent
installed dependency bytes/symlinks and the exact verified Bun 1.4.2 binary.

The existing native ChatGPT credential is read only into the parent and supplied
only through the isolated child's environment and public Pi memory-store API.
No credential file is copied; no login, refresh, models discovery, Claude OAuth,
alternate API key or paid API fallback is admitted. Catalogue presence and auth
selectors establish readiness, not account entitlement or invoice evidence.
Every physical request must use the protected token/account, Pi identity, ruled
model and exact non-strict `show_block` parameters. Only the Codex Responses
endpoint is admitted. Compressed request bytes are forwarded unchanged; the
observer decodes a copy and retains original wire hash, complete request and raw
received response/error bytes. An accepted stream must reach EOF; stopped error
streams may retain only a received prefix, with missing tails/costs unknown.
Split UTF-8 and final lines without newlines are handled. Successful bodies are
parsed as SSE regardless of their media-type header, matching the installed Pi
transport; the content type is retained as evidence. Model, terminal usage and
EOF validation establish acceptance, not a media-type string alone.
Final completed exact-model usage requires explicit safe-integer input/output,
cache/reasoning and total counters; provisional/default SDK values are insufficient.

The same empty HOME, Pi settings and freshly copied corpus apply to every arm.
Compaction, retry, cache warming, external extensions, skills, prompt templates
and telemetry are disabled. The model-visible tool roster is retained; a real
inline execution hook admits fixture reads/searches and block calls, refusing
shell, writes, delegation and external capabilities. Path resolution refuses
external symlink targets. Source/runtime are mounted read-only by bwrap; actual
personal home is absent. Public source and system runtime remain admitted for
execution, so this is private-data isolation, not proof of no public-source
contamination. Fresh writable scratch state belongs to one arm only.

With the hosted pi worker, native inference instrumentation runs after the shared
launcher gate in the same isolated worker as the resource loader and tools.
Capture files stay in worker scratch until observation drains finish; private
measurement events return the fixed artifact inventory to the parent before
worker teardown. The parent persists those bytes and shared billing-stop state.
This instrumentation adds no production worker option or application route.

Each arm first runs the shipped source CLI's actual keyless `index --force`.
The full offline server/socket/backend/provider/serializer/SSE/parser control
proves all three forms with fictional fake fetch. Separate populated list/read
and blocked-shell controls prove the fixture/tool and permission seams; neither
is an actual model result. Tests keep network guards enabled.

Each form has at most five physical requests and a 180-second response/turn
deadline. The outer process has a 240-second timeout and observes its bwrap exit;
on timeout it explicitly terminates/waits and records the signal/cleanup path.
Its PID namespace/die-with-parent containment is configured, but an absent
independent drain observation remains unknown. The protected offline controller
also unshares its network namespace; selected-fetch test doubles alone are not
global network containment. Raw errors are preserved. Fifteen total physical requests is a ceiling, not
fifteen repetitions. Existing output directories prevent automatic mixed-run
retry. Any unknown/error/model/auth/input mismatch or incomplete EOF stops the
controller without starting another arm. The parent-owned exact-hash review
receipt is required before live dispatch.

Codex rate/credit response headers are preserved. Credit presence/balance is not
proof of paid credit use; absent monetary evidence stays unknown. The route is
the ruled included subscription only. There is no API fallback or automatic
additional-charge path in this instrument. A durable shared guard stops the next
physical request or arm when exact included-limit/depleted types or exhausted
windows are reported, `usage_not_included` rejects the route, or an observed
credit balance decreases. Those stops mean included-only scope is unresolved;
they do not attribute paid charges or credit provenance to this run. Ordinary
has-credits/balance data and absent invoices remain unknown without inventing a
paid-use flag. This follows the [upstream rate/credit parser](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/rate_limits.rs)
(verified blob `4fcfc4ccd68aac340be71be3639e804e476d2ed1`) and
[rate-limit protocol](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs)
(blob `ac8eaa9f46ed24a325f0ef41d8e9a778a792fd6b`), with
[official included-limit/credit guidance](https://learn.chatgpt.com/docs/pricing).
Known paid fallback/extra charge invalidates admission. List-price equivalents and default server dollar
fields do not establish an invoice or a zero additional charge.

The final decision reads #336's frozen Claude counts and parsing evidence with
these named provider-acceptance receipts. Shipping requires unchanged accepted
inputs plus meaningful serialized `$defs`/`$ref` regression tests on both
backends and an updated shipped-form guard. D47's keyless estimates and D44's
historical 5,270 figure must be qualified by the actual counted source/version
scope. No current-runtime recount, general Pi behavioral improvement or invoice
claim follows from these three acceptance turns.

The admitted first flat request returned completed exact-model output, but the
original observer consumed its SSE body before the Pi handler, then stopped.
Its failed server turn and original receipts remain immutable and unsuccessful.
The corrected method rehydrates those exact response bytes once into the real Pi
parser/handler, then allows only the remaining four physical continuation
requests before the two originally authorized fresh shared forms. The original
request, saved SSE text-body, usage, failed process/stop and billing snapshot
hashes are frozen. The historical rejection saved `response.text()` re-encoded
as UTF-8: replay is exact to that preserved file, not an independently recorded
original HTTP-wire response. The original request wire hash remains literal.
Future failed HTTP bodies are retained as bytes before decoding a copy.
No fresh flat first-request inference is allowed. Replay is a local operation,
not a duplicate physical request or a second usage/invoice attribution.

The reconstructed first request must match every original field except its new
session cache key. New server/session/cache state and differing request wire
hash are disclosed; this is continuation of the original logical provider
context, not the same failed server session or a cache comparison. Only known
original response headers are replayed; missing content type remains unknown.
Every continuation must retain the original user/model/instructions/tools,
function-call identity/arguments and the actual parsed handler result. The
original physical request counts once, followed by at most four real flat
continuations; all three forms together remain bounded by fifteen physical
requests. The durable included-only guard starts with the original known
billing snapshots and stops before continuation on unresolved included limits.

The historical replayed flat logical turn completed with its actual parsed
comparison handler. Its native continuation terminal and usage are retained,
but the old observer treated consumer cancellation as EOF and then failed on
closing an already closed controller. Its natural upstream EOF is unknown and
its strict transport guard remains failed. No further flat inference is allowed.
The remaining-arm method binds both immutable native attempts and the successful
handler artifact, counts the two historical physical requests and their usage
once, then dispatches only fresh `shared` and `shared-trimmed` under exact review.
It is limited to that specific completed postterminal observer-close stop;
other failures, model/auth mismatches or included-only stops cannot be skipped.

Future observation writes and validates each received byte chunk before
forwarding. Pi's normal return after a completed terminal cancels its consumer,
so an independent bounded observer continues to natural provider EOF and late
metadata. Consumer cancellation cannot manufacture EOF. Cancellation before a
completed terminal is an error with missing tails unknown. Capture drains are
awaited before any next physical request and before final admission, and durable
lifecycle events distinguish consumer cancellation from natural upstream EOF.
